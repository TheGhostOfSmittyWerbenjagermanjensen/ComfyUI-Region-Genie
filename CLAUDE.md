# Region Genie: a ComfyUI custom node pack

Regional prompting and regional LoRAs for ComfyUI (MOSS Image first, then Krea 2; also Ideogram 4, Flux.1/2/3, Anima, SDXL / SD1.5). The repository root is the pack folder: it is installed as `ComfyUI/custom_nodes/ComfyUI-Region-Genie`.

Read `docs/HANDOFF.md` before larger changes: it explains the code layout, the data formats, past decisions and what is still untested. `README.md` is the front page and `docs/*.md` (one page per subject) the user-facing manual; keep them current with every user-visible change. `docs/CHANGELOG.md` has the history of every round.

## Layout

- Python nodes and server routes at the top level (`__init__.py` registers them); every `.js` file in `js/` (`WEB_DIRECTORY`). ComfyUI loads each of those files on its own, in any order: no two of them may import each other (`tests/ui_load_order.cjs`, part of `tests/run_ui.sh`, checks it).
- `region_genie.py` / `js/region_genie.js` + `js/editor/*.js`: the main node and its canvas editor (the editor is split into parts that share one object, `E`: read the header of `js/editor/parts.js` first). `regional_lora.py`: the regional LoRA engine. `region_select.py`: Select object (SAM 3.1). `llm_enhance.py`: LLM Prompt Enhancer. `wildcards.py`: Impact Pack wildcards. `control.py`: Control (ControlNet / control LoRAs). `save_image.py` / `js/save_image.js`: Save Image (Region Genie). `image_compare.py` / `js/image_compare.js`: Image Compare (two or more images in one node; read the script's header). `tiled_diffusion.py` / `js/tiled_upscale.js`: Tiled Upscale and Tiled Diffusion (Mixture of Diffusers; read its header and the section in `docs/HANDOFF.md`; never copy code from other tiled-diffusion packs: their tiling code is non-commercial). `gen_params.py`: the settings text Save Image writes for other interfaces (A1111 / Forge style): how it is read from the workflow that ran (read its header before touching it). `js/rg_shared.js`: icons (`ICONS`: the pack's own drawings; `LUCIDE`: general-purpose ones copied from Lucide, see `THIRD-PARTY-NOTICES.md`), Settings, shared helpers. `js/editor/sockets.js`: which inputs and outputs the node shows, and the step that turns shown outputs into the Python node's output numbers when a workflow is queued (read its header before touching inputs, outputs or `RETURN_NAMES`). `js/rg_keys.js`: the editor's shortcuts (one table of commands, the user's own keys, the sheet that lists and changes them). `js/rg_settings_window.js`: the Region Genie settings window (ComfyUI's Settings tab keeps a short list; most settings are on this window's pages: read the note above `SETTINGS_PAGES` in `rg_shared.js` before adding a Setting). `js/rg_tooltip.js`: the pack's own tooltip (it shows every `title` inside the pack's elements). `js/rg_menu.js`: the pack's own menu (the canvas's right-click menu). `locales/<language>/`: translations of node texts and Settings (read `locales/README.md`); `js/rg_i18n.js`: translated dropdown choices. `js/docs/<node id>.md`: the help pages ComfyUI shows under Node Info (keep them current; `tests/shot_readme.cjs` retakes the numbered picture, with the README's).
- `example_workflows/`: one workflow per supported model (ComfyUI lists them under Templates; the README and the manual link them in a table, MOSS-Image first). They are built by `tests/make_examples.cjs`, never edited by hand: run it again (and `node tests/make_examples.cjs check`) when the node's saved data, its sockets or a model's recommended settings change.
- `tests/`: see `tests/README.md`. There is no GPU in cloud sessions; tests use stubs, CPU, and a random-weight SAM fixture. Chromium is the tests' browser. When a bug is reported in Firefox, `bash tests/setup_firefox.sh` installs it and `tests/firefox_*.cjs` drive it (copy `firefox_size_row.cjs` for a new one); don't run the other suites in both browsers.

## Working agreements with the owner

- Before a decision that changes the outcome a lot (UI placement, behavior, design), present the options as multiple choice, with mock-ups where it helps, and let the owner choose. Answer their questions before building.
- A UI or visual change is settled with the owner before the full round is spent on it. While its details are still open (sizes, defaults, placement, look), stop at a working version: the code, the quick checks that show it works (syntax, the stub tests it touches), and pictures for the owner.
  - Only once the owner has confirmed the details: the manual and README, their pictures (`tests/shot_readme.cjs`), translations, the changelog and handoff, the version, and the long suites (the real-ComfyUI tests).
  - The reason: an early version of an idea is often revised, and that work would be done twice.
  - Say in the report what was left for after the confirmation. When it isn't clear whether a change is settled, ask the owner how they want to proceed.
- Must work in ComfyUI's legacy node mode **and** Nodes 2.0, on a 4K high-DPR display.
- Breaking saved workflows is acceptable, but keep them loading where it's cheap: `keepWidgetValuesByName`, add new inputs after existing ones, remap outputs by name, convert old data.
- UI: compact header controls; icons with tooltips over words, except these words the owner kept: "▼ LoRAs", "▼ All", "Separate" (the keep-separate button), "Large" (the Large editor's button, round 99), "Fit", and every "LoRA"/"＋LoRA" label ("separation" and "until" became icons in round 48). Reuse existing icons; a button is never labelled with a character (✕, ↑ …): take a general-purpose icon from Lucide into `LUCIDE`, draw a pack-specific one into `ICONS`.
- Scroll bars (a guideline, not a law): avoid them where it can be done, above all in small pop-ups and menus. Never a horizontal one where it can be helped (most mice can't scroll sideways). A vertical one can be right in some places: when a design decision would go one way or the other because of a scroll bar, ask the owner.
- Colors: the pack's highlight color and its "switched on" color are the user's (Settings; `--rg-accent`, `--rg-on` and their shades, `applyPackColors()` in `js/rg_shared.js`): a style sheet takes them from the variables, never as a fixed blue or amber, and what is drawn on a canvas asks `accentColor()`.
- Tooltips (node inputs / outputs, Settings, every editor control; set them the plain way, `el.title = "…"`): concise but complete. A shortcut is written in brackets at the end of its sentence with its default key, `(Ctrl+Z)`, `(V)`: the pack's tooltip shows it as a key, and `E.keyTitle(el, text)` / `keyed(text)` put the user's own key there. Every shortcut is a command in `COMMANDS` (`js/rg_keys.js`): the key handler asks `keyIs(e, id)`, never compares a key itself; hints and messages take the key from `keyText(id)`. Another node's keys are commands in the same list, with a `ctx` and a `group` of their own (Image Compare: `compare`, "Image Compare node"): the sheet shows the pack's shortcuts in one place, a section per node, and a key is only taken from a command of the same `ctx`, so two nodes may use the same key. Such keys act only while the pointer is over their node. A key that can't be changed (a mouse gesture, Image Compare's 1 to 9) is a row in `FIXED`. A tooltip that explains several things (options, states, outputs) puts each on its own line (`name: Description.`). Every sentence starts with a capital letter, also after a ":", unless its first word is a lowercase field / option name (`sidecar .json: The workflow …`). `tests/tooltip_rules.cjs` has the rules; `tests/real_tooltips.cjs [vue]` checks every tooltip.
- The owner often can't test right away: explain behavior changes clearly, and end every task with what was tested and what wasn't (real GPU runs never are).
- After each round, update `docs/HANDOFF.md` (current design, open items), `docs/CHANGELOG.md` (the round: asked, decided, built, tested), the manual (`README.md`, `docs/*.md`) and, for anything a cloud session can't check, `docs/HARDWARE-CHECKLIST.md`. Raise the version in `pyproject.toml` (and the version badge at the top of `README.md`) with every user-visible change. The README is a short feature tour: detail goes into the manual pages, and its pictures are retaken with `tests/shot_readme.cjs` when the node's look changes. In pictures, a LoRA is shown with trigger-word chips, and no model name is shown in red (not found): the script makes demo files for that.
- Before implementing anything (features, fixes, docs), fetch from GitHub and make sure the local copy matches the latest version of the branch the working branch is based on (its base branch: often `main`, but it depends on the situation), plus any newer commits on the working branch itself. If a PR from the working branch has been merged, start the new work from the current base branch.
- When an instruction is unclear or could be read more than one way, ask the owner before acting on it.

## Checks before pushing

GitHub Actions (`.github/workflows/tests.yml`) runs the syntax checks, `tests/run_py.sh` and `tests/run_ui.sh` for every pull request and every push to `main` (not for a branch without a pull request: run them here before pushing); the real-ComfyUI tests are manual.

- `node --check --input-type=module < js/<file>.js` for every changed JS file (also in `js/editor/`); `python3 -m py_compile` for Python.
- `python3 tests/verify.py` picks and runs the checks for what changed (the `verify` skill; `--quick` while working, the full run before a push, `--all` before a release). Its table `RULES` is the list of what runs when: a new check file gets a line there.
- In the report: every test this change edited or deleted, with the reason; every check listed as NOT RUN.
- After three rounds of fixing with the same check still failing, stop and ask the owner.
- `tests/real_layering.cjs` needs a line for every new place where text is typed, a `menuFrom()` line (or one in `popExtras()`) for every list, menu or picker a pop-up's control opens, and a `nativeTips()` call for every new pop-up or panel.
- When a node text (name, input, output, tooltip, dropdown choice) or a Setting changed: `node tests/i18n_extract.cjs` (rewrites the English reference `tests/i18n_en/`), `python3 tests/test_i18n.py --todo` lists exactly the entries whose English is new or changed: translate only those in every `locales/<language>/` (never re-translate or re-review the rest), `python3 tests/test_i18n.py --done`, then `tests/real_i18n.cjs [vue]` (restart ComfyUI first: it reads locale files at start).

## Never commit

API keys, tokens, passwords, personal paths or email addresses, model files (`*.safetensors`), `llm_cache.json`, ComfyUI settings files. Keys a session needs go in the cloud environment's network secrets, never in the repo or in environment variables.
