# Region Genie (ComfyUI node pack): handoff summary

**State (Nov 17, 2026):** version 0.34.1 (`pyproject.toml`), GPL-3.0. The GitHub repository is the source of truth; work happens on branches and reaches `main` through pull requests the owner merges. The history of every development round is in `docs/CHANGELOG.md`; this file describes the pack as it is now.

The pack used to be called **Regional Mask Kit** (renamed Nov 10, 2026). The compatibility code for the old names was removed in round 24 (section 7).

## 1. Goals and working agreements

- **Purpose.** A ComfyUI node pack for regional prompting and regional LoRAs.
  - Built mainly for **MOSS-Image** (text encoder Qwen3.5 9B loaded as CLIP; MOSS layout JSON).
  - Also **Ideogram 4** (Qwen3-VL 8B; caption JSON).
  - With plain text: **Krea 2**, **Flux.1**, **Flux.2 / Klein**, **Flux 3**, **Anima**, **SDXL / SD1.5**.
  - After MOSS, Krea 2 matters most to the user.
  - All of these also work image-to-image (Edit Mode, round 4).
- **Must work in both** legacy node mode and **Nodes 2.0**, on a **4K, high-DPR display**.
- **Breaking workflows is acceptable**, but keep saved workflows loading where it's cheap: `keepWidgetValuesByName`; new inputs added *after* existing ones; `remapOutputs`; legacy-data conversions.
- **Delivery each round:** commits on a working branch, a pull request when the owner asks, and a report of what was and wasn't tested. Update this handoff, `docs/CHANGELOG.md` and the manual (`README.md`, `docs/*.md`) every round.
- **Process preferences:**
  - UI and visual changes are settled with the owner first (round 73, CLAUDE.md has the rule): a working version, quick checks and pictures while details are open; docs, pictures, translations, version and the long suites only after the owner confirms.
  - Before decisions that change the outcome a lot (UI placement, behavior, design), present options as multiple choice with mock-ups and let the user choose.
  - Answer the user's questions before building.
  - "Look into whether X could be added": build it unless it's an extreme rewrite.
  - The user often can't test right away, so explain behavior clearly.
- **UI preferences:**
  - Keep header controls compact.
  - Icons with tooltips over words, except the words the user kept: "▼ LoRAs", "▼ All", "Separate" (the keep-separate button), and every "LoRA"/"＋LoRA" label ("separation" / "until" were words until round 48, now icons).
  - Reuse existing icons where possible.
- **Sensitive data:** treat the user's email as private.

### Region Genie node

**Inputs** (widget order matters for old workflows):
- Required: `width`, `height`, `scene_prompt_positive`, `scene_prompt_negative`, `image_mode`, `min_region_pixels`, `paint_data` (hidden JSON state).
- Optional, in order: `model`, `clip`, `vae`, `image`, `size_from_image`, `size_from_latent`, `import_mode`, `scene_prompt_background`, `prompt_format`, `mode`, `edit_area`, `import_json`.
- Hidden combos with editor controls: `image_mode`, `prompt_format`, `mode`, `edit_area`.
- **Round 6:** `min_region_pixels` and `import_mode` are now **Settings only** (`RegionGenie.Main.MinRegionPixels`, `RegionGenie.Main.ImportMode`). The editor sends them in `paint_data` (`minPixels`, `importMode`) at each run, and `run()` prefers those over the hidden widgets, which are only a fallback (API use, old frontends).

**Outputs (13):** model, positive, negative, latent, prompt, color_map, masks, bboxes, elements, character_boxes, region_info, width, height.

**`prompt` format.** `prompt_family(model, clip, choice, hint, edit=False)`: the format control, else the model, else the clip's text-encoder class, else the front end's `promptFormatHint` (follows the `prompt` output to the text encoder and its loader; checkpoint file-name guess kept on purpose), else MOSS JSON. MOSS in Edit Mode → plain text.

**`paint_data` keys added at run time by `serializeValue`** (not stored in the canvas state): `autoSeparate`, `promptFormatHint`, `edit` (edit mode), `editMask` (edit mode), `llmCache`, `minPixels`, `importMode`.

## 3. Code layout

### Python

- **`__init__.py`:** mappings, legacy IDs, `SEARCH_ALIASES`, `_OBSOLETE` cleanup; imports `lora_triggers`, `llm_enhance` and **`region_select`** (they register routes).
- **`region_genie.py`:** the `RegionGenie` node.
  - Parsing, label map, palettes, `layer_centre`, the MOSS / Ideogram / text builders, `prompt_family`, `auto_separate_on`, `layout_from_json` + `POST /region_genie/convert_layout`, the LLM hook.
  - `shape_verts(kind, sides, bw, bh, radius)`: **round 6** adds `roundrect` (8 arc points per corner; radius = % of the shorter side, clamped 0-50, default 20; corners stay round because bw/bh are used). `layer_mask` passes the layer's `bw`, `bh`, `radius`.
  - Edit Mode helpers (round 4): `edit_size`, `fit_image`, `limit_image`, `empty_latent`, `lora_edit_format`, `REF_MODELS`, `MOSS_EDIT_FORMATS`, `VISION_PREFIX`.
  - **Round 5 edit mask:** `EDIT_MASK_DEFAULTS = {grow 8, feather 16}`; `grow_mask(m, px)` (scipy EDT, box-blur fallback); `edit_mask(change, keep, whole, grow, feather)`: kept regions are excluded, and the soft edge toward a kept region falls outside it. The latent's `noise_mask` uses it; `pdata["editMask"]` (grow -256..256, feather 0..256) overrides the defaults.
  - Table rows carry `keep`; `_regional_loras` passes `share_background`.
- **`regional_lora.py`:** the regional LoRA engine and the two LoRA nodes.
  - Forward hooks, `ModelArch` / `model_arch`, `Layout`, `TokenRegion`, token helpers, `regional_lora_patch`.
  - **Round 5:** `RegionSeparation(regions, strength, until, share_bg=False)`: with `share_bg`, pairs that involve background (label 0) image tokens aren't penalized, in both the joint and cross-attention paths; captions stay restricted. `RegionalLoRAs` has a new last required input `share_background` (BOOLEAN, default False).
- **`region_select.py` (round 7, new):** Select object, using ComfyUI's native SAM 3 / SAM 3.1 support.
  - Routes: `POST /region_genie/sam_select`, `POST /region_genie/sam_release`, `GET /region_genie/sam_models`. Route registration is skipped when `PromptServer.instance` doesn't exist (tests, scripts).
  - The model is loaded with `comfy.sd.load_checkpoint_guess_config` from `models/checkpoints` (default `sam3.1_multiplex_fp16.safetensors`; another file with "sam3" in its name is used when the Setting's file isn't there). `mm.load_model_gpu(model)` runs before each request, so ComfyUI manages VRAM: idle → moved to system RAM when a workflow needs room.
  - **Trunk cache:** the ViT trunk output is computed once per image (key: model, path, mtime, size) and kept on the CPU. Each click swaps `vision_backbone.trunk` for a tiny module returning the cached output (`_CachedTrunk`, under a lock), then calls ComfyUI's own `forward_segment` / detector forward. Tested to be bit-identical to the uncached path.
  - Points + box: one `forward_segment(point_inputs, box_inputs)` plus one mask-refine pass (as SAM3 Detect does). Text ("find all"): the clip encodes each comma-separated phrase with `:64` appended unless it already has `:N` (SAM 3's text encoder returns only 1 match per phrase otherwise); detections over the threshold are sorted by score; the best 16 (`REFINE_MAX`) get `_refine_mask` from `comfy_extras.nodes_sam3`, the rest keep the detector mask. Each mask carries its phrase as `label`.
  - Returns masks as run-length runs (zeros first, the editor's bitmap format) at the size the editor asks for (its raster grid).
  - `queue_busy()` → 409 `busy` while a workflow runs (the editor retries every 2 s). `keep_loaded` false: unload on release, and after 180 idle seconds (`threading.Timer`). Unload = drop references, `gc.collect()`, `cleanup_models()`, `soft_empty_cache()`.
  - `resolve_image` only accepts `input` / `output` / `temp` paths inside those folders (path traversal refused).
- **`llm_enhance.py`:** LLM Prompt Enhancer back end.
  - **Round 5 cache:** session-only by default (`_cfg = {disk: False, days: 30, max: 500}`); `configure()` from Settings (route `POST /region_genie/llm_cache_config`, plus a fallback read of `user/default/comfy.settings.json`); disk files (new and old cache folders) are deleted when disk caching is off; entries are stamped with a time and pruned by age and count.
- **`model_paths.py` (round 18, new):** model files anywhere. `full_path(folders, name)` (a full path to an existing model file as it is, else ComfyUI's lookup in each folder type in turn), `absolute_names()` (a re-entrant context manager that, while active, lets `folder_paths.get_full_path(_or_raise)` return a full path, so core loaders that take a name, `LoraLoaderModelOnly`, `ModelPatchLoader`, `LoadDA3Model`, can load one; restored afterwards), `browse(path, folders)` + `GET /region_genie/browse` (sub-folders and model files of one folder, hidden ones skipped; `rel` = the name ComfyUI knows a file by when it is inside one of the folders), `GET /region_genie/model_exists`. Used by control.py (Anima: `ANIMA_FOLDERS = model_patches, controlnet`), `regional_lora.load_runtime_lora` / `merge_loras`, `region_genie.lora_edit_format`, `lora_triggers`, `region_select.resolve_model`.
- **`lora_triggers.py`, `bbox_masks.py`:** unchanged (lora_triggers: full paths, round 18).

### JavaScript (`js/`)

- **`region_genie.js`**: registers the extension and calls `buildEditor(node)`. The editor itself is in **`js/editor/`** (split in round 24; no behavior change):
  - `parts.js`: the list of parts, in the order they run, and `buildEditor`. **Read its header first.** All parts of one node share one object, `E`. A function or value only its own part uses is a local; one another part uses is published on `E` (`Object.assign(E, …)` at the top of the part for functions, `E.name = name` after a value's declaration) and read as `E.name` elsewhere; a variable that changes and is used by several parts lives on `E` only (`E.state`, `E.tool`, `E.view` …). Each part is a generator with one `yield`: first every part runs up to its yield (publishing its functions, so the order of the files doesn't matter for calls), then the bodies run in order.
  - Without a node (plain modules): `shared.js` (constants and values shared by every Region Genie node on the page (tool versions, the layer clipboard, sizes)); `state.js` (paint_data: the editor's saved state (format, loading, converting older data)); `geometry.js` (geometry without a node: edge snapping, masks, outlines, shapes, bitmap layers); `style.js` (the editor's CSS); `graph.js` (graph helpers: chaining node callbacks, links, moving links of old workflows to renamed outputs); `colors.js` (region colors and palettes).
  - Parts, in order: `core.js` (the node's widgets, last-run wildcard results, the expand button, and the editor's state variables); `toolbar.js` (the editor's elements, the tool buttons (with versions), the tool options strip on the canvas, Arrange, opacity and labels); `footer.js` (the footer: Export / Import, image mode, Generate / Edit, wildcards and the seed control; keeping the footer in step with the settings); `model.js` (the connected model: the footer pick, the guess from the graph, layout / standard, what the settings row shows); `rows.js` (the Control and Edit rows under Whole image, the per-region control / keep switches, and the message bar); `canvasUi.js` (the brush size slider on the canvas, the list header's options (keep separate, edit mask), sub-sections and the list height); `sizeRow.js` (the image size row at the top of the node (aspect ratio / presets / manual)); `view.js` (image size from the graph (linked inputs, Resolution Selector), canvas size and view (zoom, pan, coordinates), layer geometry); `regions.js` (regions, undo / redo, what can be done to a layer (add, duplicate, copy / paste, merge, delete …), tool switching and hints); `render.js` (drawing the canvas, hit testing, and the region label map (what the outputs will contain)); `selectTools.js` (fill, magic wand, Select object (SAM 3.1) and Arrange (flip, align, grow / shrink)); `pointer.js` (mouse, pen and keyboard on the canvas); `popups.js` (the pop-up editors for prompts, and the editor's keyboard shortcuts); `list.js` (the region list: one tree of regions with their LoRAs, layers and palettes); `llm.js` (lLM Prompt Enhancer: the sparkle buttons, requests and results); `lifecycle.js` (the backdrop image, layout import / export, and the node's lifecycle (load, save, resize, run results)).
  - When adding code: put it in the part it belongs to; if another part needs it, publish it on `E` the same way. A new part goes in `PARTS` in `parts.js` at the place its body must run. ComfyUI loads every `.js` under `js/`, also in subfolders, so nothing else needs registering.
  - **Round 5:** shared-background right-click menu on the four-tiles button (`loraOpts.shareBg`, icon `allSeparateShared`); per-region keep/change in edit mode (`r.keep`, pencil/lock toggle, hatched overlay, 🔒 label prefix); edit-mask grow/feather fields in the list header (`state.editMask`, empty = follow Settings); the Whole image row toggles on a click anywhere except its buttons.
  - **Round 6 footer ("Footer B"):** a `Generate | Edit` segmented control, `change` select (edit only), format select ("auto · MOSS" after a run), LLM Settings sparkle icon, tag autocomplete icon; Export / Import on the right. Image mode is a segmented icon pair (backdrop / color map) in the top bar, shown only with an image connected and not in edit mode; with color map a min px field writes the Setting.
  - **Round 6 tools:**
    - variant tools with right-click menus and a corner triangle: lasso / lasso erase (plain, spline, magnetic), magic wand (connected, all similar colors), fill (normal, closing small gaps). `LASSO_MODES`, `TOOL_NUMS` (wandTol, fillGap), `refreshVariantButtons()`, `syncToolOpts()` (tolerance / gap fields).
    - magic wand (W): uses the backdrop pixels (`backdropPixels`), flood or global match, per-channel tolerance.
    - magnetic lasso: Sobel edge map of the backdrop (`edgeMap`, ≤1024 px), `snapToEdge` / `snapSegment`, radius `magnetRadius()`.
    - fill closing gaps: chamfer `distanceMap`, flood the area that stays open after growing the walls by the gap, then grow back.
    - rounded rectangle (`radius` field, layer key `radius`), Alt+drag draws a shape from its centre, Shift+click straight lines for brush/eraser (`lastStrokeEnd`), Alt+click eyedropper for painting tools.
    - Arrange pop-over (`.rg-arrange`, fixed in `document.body`): flip H/V, align ×6 + centre, grow/shrink N px. Rewritten in round 45 (selectTools.js; `tests/ui_arrange.cjs` judges every case by the layer's pixels, `__rgLayerMask`): **flip** mirrors the picture on the image about the middle of the layer's pixel box (`pixelBox()`): the layer's own content is mirrored, `rot` becomes `-rot` (a shape upside down: `180 - rot`, since shapes are only left-right symmetric) and the layer is moved so that point stays; an unturned paint layer keeps its frame (fills still go into it). **Align** uses `pixelBox()` (a raster over the layer's box, so parts off the image count). **Grow / shrink**: a shape with no ops stays a shape (`growShape()`: the box is refitted to the outline moved by g with pointed joins, `offsetOutline()`; exact for rect, ellipse, rounded rect (radius ± g), triangle, regular polygon and star while unstretched; a heart by its box); everything else becomes one bitmap op from an exact distance transform (`distanceSq()` in geometry.js; the old chamfer distance cut corners at 45°), plus, when growing with nothing erased, the shape's and the lasso outlines' stroke with mitre joins so pointed corners stay pointed. The raster covers the layer's pixel box plus the room it grows into, also outside the image, on the image's pixel grid; the bitmap op's `x0..y1` then reach outside the frame (Python's renderer takes any box). Cut off at the image's edge, a layer grown past it crept towards that edge with every grow + shrink (the owner's report). Shrinking to nothing is refused with a hint.
    - shared helpers `rasterSize`, `regionLabels`, `flood`, `commitMask` (into the selected plain layer of the active region, else a new layer).
  - **Round 8 Select object fixes:** the tool button uses icon `samSelect` (`addTool(key, title, icon)`; it used to look up `ICONS.object`, which doesn't exist, so the button was blank). ✓ / ✕ buttons after the find field (`pickOkBtn` / `pickNoBtn`, icons `check` / `close`, kept in step by `syncPickBtns()` on every draw). `pickSettle()`: leaving the tool (or the image going away) adds a finished selection, or waits for the answer in flight (`pick.acceptOnAnswer`), instead of discarding it. `pickNext()`: Shift+click / Shift+drag adds the selection so far and starts a new one. `pickAccept` adds to the active region in both modes (`commitMask`: into its selected plain layer, else a new layer); `asRegion` is only used by Shift+Enter (find all, one region each).   - **Region opacity (round 72).** `E.fillNow()` / `E.setFill(v)` / `E.fillDefault(img)` in core.js: how solid the composite is drawn, one value with an image under it (`properties.rg_fill_image`, Setting `cmFillImage`, 50) and one without (`rg_fill`, `cmFill`, 50).

The control (toolbar.js, `E.syncOpacity`): a button (`.rg-opac`) in the canvas's top right strip (`.rg-imgmode`, always shown since round 72); its slider (`.rg-oslider`) drops down on hover, while dragged, or after a click (`.open`) until a click elsewhere.
    - **Edge lines (round 73).** `edgeLines()` in render.js, below 100% and with Setting `cmEdge` (px, 0 to 10, 3.5) above 0. Each region is outlined along its own whole shape, hidden where regions in front cover it.

      - `EDGE_GL` (module level, one WebGL canvas for the page, up to 8 textures = 24 regions): per pixel and region, m = the shape here, e = the least of m on 1 to 3 rings of 12 points a line's width around; line = color x (m - e) x what the regions in front leave.

## 4. Current design and why

The reasons behind the parts a new session is most likely to trip over. Each ends with the round(s) in `docs/CHANGELOG.md` that have the details.

**Model files (Settings, Edit rows, LLM)**
- Every model-file field is a button showing the file's name; a click opens ComfyUI's classic menu (`LiteGraph.ContextMenu`) through `fileField()` / `openModelMenu()` in `rg_shared.js`, in legacy mode and Nodes 2.0 alike. Reasons: rgthree's Auto Nest only wraps that menu, and the Nodes 2.0 dropdown isn't open to extensions. Region Genie adds a search across the whole tree, and its own filter box when ComfyUI leaves it out. (Round 23)
- **Do not use ComfyUI's native Settings combo for file lists.** It builds a component per option and froze the tab with a large LoRA library (1000 files × 25 settings). `tests/real_settings.cjs` guards this with 10 000 LoRAs. (Rounds 21, 22)
- **Do not pass file names through vue-i18n.** A backslash or `@` in a name is message syntax there and made settings disappear on Windows. (Rounds 15, 18)
- 'Check model files' (Settings > Model files): `checkModelFiles()` in `rg_shared.js` looks up every set file with the same `fileKnown` the fields use for their red state; `rg_llm.js` adds the LLM presets' files through `LLM_FILES.list`. `fetchModelFiles` keeps one entry per folder and name (a name in two model folders used to be listed only under the first, so a field could show red wrongly). (Round 24)
- Values: a plain name in the setting's home folder, `folder:name` from another model folder, or a full path from Browse… (`model_paths.py`: `split_folder`, `full_path`, `absolute_names()` so core loaders accept a full path). Browse… is behind the 'Browse… for model files' switch. Inside the Settings dialog a menu must live in the dialog element (`keepMenusIn`). (Rounds 18, 19, 23)

**Control and Edit rows (under Whole image)**
- `state.controls` is a list of rows (kind, strength, start, end); ＋Control is always there. ControlNets chain and LLLite patches stack; MOSS-Image's control LoRA and Flux.1's depth / canny LoRAs share one model input, so Python uses only the first such row and says so in `region_info`. A region's control switch applies to every row. (Rounds 10, 18, 23)
- Edit rows show only in Edit Mode: the Settings edit LoRA for the model (its ✕ sets `editOff` for this node), plus the node's own `editLoras` from ＋Edit. Edit / control LoRAs are tagged entries in `sceneLoras`, managed by `syncEditLoras` / `syncControlLoras` / `pruneManagedLoras`, and not listed under Whole image. (Rounds 15, 18, 23)
- A Control row that won't be used (a second row needing the model's one extra input) is marked in the editor: `usesConcat` / `controlUnused` in `js/editor/rows.js` mirror `control.uses_concat`; keep the two in step. (Round 24)
- The model is the last run's, else a guess from the graph, else the footer pick (`rg_model_pick`); it decides the prompt format and which files the rows use. The stored name is "MOSS-Image" (older "MOSS Image" converts on load). (Rounds 10, 12, 17)

**Editor**
- One-row toolbar with ▾ version buttons and a tool-options strip on the canvas; the footer is one row (`flex-wrap` off) because wider system fonts wrapped it. (Rounds 11, 21)
- Pop-up editors open from the expand button (double-click selects words), can leave the node, and close only by ✕ / Esc. (Rounds 10, 12)
- MOSS-Image's layout / standard switch: layout unless standard was chosen while there are regions (`rg_moss_layout === false`); standard by itself with no shown region or in Edit Mode, where a click does nothing; the first region on an empty canvas clears a standard choice (`layoutHad` in `syncLayoutBtn`, reset in `load()`). (Rounds 12, 20, 25)
- 'Keep all regions separate' has three states in `loraOpts`: `allRegions` (on for this node), neither (automatic: a run turns it on for a model without a layout format, and reports `auto_separate`), `autoOff` (off for this node, also where it would turn on). The button shows on for the first, and for the second after such a run; a click always changes what it shows. (Rounds 3, 25)
- Gradient fill: a layer with `grad: {k, a, b}` (layer units) whose region fades. JS draws it with `fadeLayerOn` (only on a canvas that holds that layer alone); Python: `layer_fade`, `render_layers(..., soft)`, `soft_mask`. The index map (color_map, boxes, prompt) takes the pixels from half strength; `masks` carries the strength. Keep the two sides in step. (Round 26)
- Pop-up editors are at z-index 10000; anything that must show over them needs more (the autocomplete lists: `.rg-ac`, 10002; the wildcard list 10001; the color picker and LLM pop-up are far above). (Rounds 12, 26)
- Holes are a ✂ switch per layer: `region: 0` plus `owner` for the region it is listed under. Layout mode shows as off when no region is visible. (Round 20)
- Number fields size themselves through a page-wide observer in `rg_shared.js` (`autoNumber`). Rows that redraw on a timer must not replace an element under the mouse, or its tooltip never appears (`setHTML`). (Round 12)
- The workflow loader keeps unknown keys (it once dropped new ones on reload). New node inputs go **after** existing ones: values are stored by position, and an input added in the middle shifted them (`keepWidgetValuesByName` now also resets invalid values). (Rounds 10, 20)

**Other nodes**
- Save Image (Region Genie): design in `docs/superpowers/specs/2026-11-13-save-image-design.md`; every node keeps the ✨ title icon (a custom icon was tried and rejected). (Round 13)
- Select object keeps SAM 3.1 loaded through ComfyUI's model management, so ComfyUI frees it when it needs the memory. (Rounds 7, 8)
- Wildcards send seed 0 while no field has wildcard syntax, so the node stays cached. (Round 9)
- LLM Prompt Enhancer: presets live in `user/default/region_genie/llm_presets.json`; every pop-up field is also a Settings row (`LLM_FIELDS`, `LLM_ROWS`). (Round 19)

**Tooltips:** one item per line, capitalized sentences; `tests/tooltip_rules.cjs` and `tests/real_tooltips.cjs [vue]` enforce it. (Round 14)

### Languages (round 31, phase 1)

After changing an English node text or Setting: `node tests/i18n_extract.cjs`, `python3 tests/test_i18n.py --todo` (exactly the new / changed entries, per language), translate those, `--done`, restart ComfyUI, `node tests/real_i18n.cjs [vue]`. ### Tiled Upscale and Tiled Diffusion (rounds 75-76; `tiled_diffusion.py`, `tests/test_tiled.py`)

**State when this was written (Nov 25):** a working version the owner has NOT yet tried on a real model. The owner tests on Anima (and uses Forge Neo's Mixture of Diffusers as the reference for speed and quality). English docs and the four translations of the two nodes are written (`tests/i18n_extract.cjs` leaves the samplers', schedulers' and resize methods' names untranslated). Not done yet: an example workflow, `tests/real_*` for the two nodes, README picture, the owner's confirmation of defaults.

**Branches.**
- `claude/sharp-tesla-1gt9qf` (the working branch): `no_metadata` (0.56.0, round 74), the two tiled nodes with `tile_blend`, and "step 1" (the regional engine steps aside in tiled runs). No PR open.
- `claude/tile-aware-regions`: everything above plus "step 2" (regions cut per tile). The owner asked for it on its own branch because of its risk and uncertain benefit. It is merged into the working branch only when the owner says so, after trying it. Keep it up to date by merging the working branch into it.

**What the owner decided.**
- Mixture of Diffusers (their experience: best quality for the speed; small tiles fit small cards; no extra model to install). It stands alone (no dependency on other packs) and lives in this pack.
- Both nodes: the all-in-one Tiled Upscale, and the MODEL → MODEL Tiled Diffusion.
- `upscale_model` is a widget on the node (round 78; "none" = resize only; before, an optional input), and a `color_fix` like the other pack's; `tile_overlap` is the seam control they meant; `tile_blend` added, 1 = the paper's blend.
- Shelved: giving each tile its true position in the picture (below). Not wanted: per-tile layout prompts for MOSS-Image / Ideogram 4.

**How it works.**
- Written from the paper (https://arxiv.org/abs/2302.02412). No code from other implementations: shiimizu's ComfyUI-TiledDiffusion, the DazzleNodes fork and Forge Neo's copy all descend from the A1111 extension, whose tiling code is CC BY-NC-SA. Never copy from them.
- `TiledModel` is an `APPLY_MODEL` wrapper (`comfy.patcher_extension.WrappersMP.APPLY_MODEL`, key `region_genie_tiled`). It gets x in sigma space with cond and uncond already in one batch, and returns the denoised latent; blending denoised tiles equals the paper's blend of noise predictions.
- `TileGrid`: tiles of even size at even positions, spread evenly, the last ending at the edge (`tile_starts`). Pixels become latent cells with `latent_format.spacial_downscale_ratio` (`px_per_cell`: 8, or 16 for the Flux.2 latent).
- Weights: `gaussian_weights(h, w, blend)`, variance 0.01 x blend² on a tile of length 1, each axis with its own length (the original and Forge use the width for both; the Dazzle fork corrected that, and so do we). `TileGrid.share` holds weight / sum of weights per tile, worked out in float64 (a narrow Gaussian's edge underflows float32).
- Batch layout: sample-major, [sample 0: tile a, tile b …, sample 1: tile a …], so chunking the batch by `cond_or_uncond` still gives the cond / uncond halves. Batches are evened out (`per_call`).
- Per tile: `c_concat`, `denoise_mask` and anything else whose last two sizes are the latent's are cut; tensors with a row per sample are repeated (`repeat_interleave`); lists element by element; the rest is passed as it is. `_control` cuts ControlNet residuals that are 4-D images at a whole-number scale (UNets); otherwise the control is dropped with one warning.
- Not tiled (plain call): a latent that isn't 4-D / 5-D, `latent_shapes` in the conds (packed latents), or one tile.
- 5-D latents (Anima, Qwen: a frame axis of 1) are cut on the last two axes. Only tested with a stand-in.
- `tiled_model()` puts its key FIRST in `model.wrappers[APPLY_MODEL]` (ComfyUI runs wrappers in key order, the first outermost) and passes `transformer_options["rg_tiles"] = {"canvas": (H, W), "boxes": [(y, x, h, w) …], "rows": B}` (latent cells, the boxes of that call) to everything inside.
- Round 78: `load_upscale_model(name)` (via `UpscaleModelLoader`, the last one kept in `_loaded`); `match_colors(image, reference)` = image + Gaussian-blurred (sigma `COLOR_SIGMA` = 8 px of the original) difference to the original, worked out at the original's size, applied after enlarging and after decoding when `color_fix` is on (our own method: the other pack's wasn't read); `run` logs one line of timings per stage. `gen_params._upscaler` reads the node's own `upscale_model` name. Owner's first GPU report (MOSS-Image, 1024 → 2048, 8 steps, denoise 0.2): works, 18-22 s against 18-20 s for their DazzleNodes subgraph, but they ran ours with 2048 px tiles (one tile, no tiling) against 1024 there; sampling was only about 5 s of it, so the timing line is there to find the rest (suspects: VAE encode / decode of 2048 px untiled against their tiled "fast" ones). Offered, not built: VAE tile sizes on the node.
- Round 79: `vae_encode_tile_size` / `vae_decode_tile_size` (0 = whole; `vae_encode` / `vae_decode` call `encode_tiled` / `decode_tiled` as ComfyUI's tiled VAE nodes do, overlap `min(64, tile / 4)`); `preview` (off: `_no_preview` sets `comfy.cli_args.args.preview_method` to NoPreviews around the sampler call and puts it back; the progress bar still moves). Owner's timing on MOSS-Image, 1024 → 2048 with 4x-UltraSharpV2: enlarge 13.2 s, encode 0.4, sample 4.0 (9 tiles, 2 steps, 6 calls), decode 0.5: the upscale model is the cost, not the tiling or the VAE; the line now splits loading the upscale model, enlarging and the color fix.
- `TiledUpscaleRG.run`: `upscale_pixels` (upscale model via `comfy_extras.nodes_upscale_model.ImageUpscaleWithModel`, then `comfy.utils.common_upscale` to a multiple of 2 cells) → `vae.encode` → `tiled_model` → `nodes.common_ksampler` with `start_step = redraw_start(steps, denoise)`, `denoise=1.0`, `force_full_denoise=True` (only the last steps x denoise steps are run, like KSampler (Advanced); a sampler's own `denoise` would run all steps: the owner's point in round 77) → `vae.decode` (ComfyUI falls back to tiled VAE by itself when memory runs out).

**Step 1 (working branch): with the regional engine.** `_ActivateRegionalLoRAsWrapper.__call__` (regional_lora.py) returns `executor(*args, **kwargs)` when it sees `rg_tiles`: regional LoRAs and separation are left out of a tiled run, with one log line. Before, they were wrong inside tiles: off on transformer models (the tile's sequence length doesn't fit `_layout`), and on UNets the whole layout was squeezed onto a tile when a tile was half the canvas per side.

**Step 2 (branch `claude/tile-aware-regions`): regions cut per tile.**
- `_state.tiles` / `_tiles()` = (canvas, boxes, rows); row r of the batch is tile r % len(boxes).
- `TokenRegion.grid_mask(h, w, src, tile)`: the mask resized to the whole latent (cached, key `("c", H, W)`), the box cut out, then as before. `weights(…, tiles)` gives (B, L, 1), `spatial(…, tiles)` (B, 1, h, w); a sequence without image tokens stays (1, L, 1). The forward hook skips a layer whose batch isn't 1 or B (a thrown error would set `p.broken` for good).
- `RegionSeparation.labels(…, tile)` per box; `tile_bias()` builds (B, 1, nq, nk) on the device from label vectors, cached only while that batch of tiles is in the model (`_tile_key`); `override(…, tiles)` uses it. Text-only layers use the ordinary `bias()`.
- Effect for the plain-text families (Krea 2, Flux, Flux 3, Anima, SDXL / SD1.5): a region that isn't in a tile has no image tokens there, so its caption reaches nothing in that tile: each tile hears only the regions it shows. MOSS-Image and Ideogram 4: regional LoRAs become per tile, but the layout prompt still describes the whole picture to every tile.
- A batch that doesn't fit `rg_tiles` (rows x boxes, tile size) runs without regions and logs a warning.
- No extra model calls. Cost: the non-fused attention path while separation is on (as in any run with separation) and one (B, 1, L, L) bias per call.
- Tested on the CPU only: the cuts, batch layout, per-tile separation for a Flux-style joint layout and a UNet, both wiring orders through ComfyUI's sampler with a tiny random UNet. NOT tested: any real model, a real LoRA through the per-tile masks, the layouts of Anima / Krea 2 / MOSS-Image / Flux 3 in tiles, memory and speed.

**Research results worth keeping (Nov 24-25; scripts under the session scratchpad are gone after the session).**
- Forge Neo (`Haoming02/sd-webui-forge-classic`, branch `neo`, `extensions-builtin/sd_forge_multidiffusion`): a slimmed copy of shiimizu's code. No speed trick, no position handling for any model, img2img only, tile batch 1 by default (slider to 8). It is fast because it only cuts, calls the model once per batch and adds.
- DazzleNodes fork: default tile batch 4; it forces batch 1 only when its per-tile position fix is on (Flux, Flux.2, Qwen-Image; not Anima, which it doesn't detect). Its docs give the denoise ladder used in our tooltips (0.025 polish, 0.18 detail, 0.28-0.42 invention, above 0.6 tiles forget the picture).
- The owner's Forge vs ComfyUI speed comparison was on Anima, where the fork batches too: batching doesn't explain that difference (unknown: backend, settings).
- **True positions per tile (shelved by the owner).** Measured with tiny random models on the CPU: several tiles with different position offsets in ONE batched call work for Flux.1 / Flux.2 / Krea 2 / Qwen-Image (a `post_input` patch that adds the offset to `img_ids`, offsets passed in `transformer_options`), MOSS-Image (object-patch `diffusion_model.rope`), Z-Image (`rope_embedder`), Chroma (`pe_embedder`); results equal single runs to float noise. The effect comes only through the text tokens' positions (shifting the text ids the same way undoes it). On Anima a shift changes nothing at all. So it matters for reference-latent tiling and high denoise, hardly for low-denoise upscaling, and a 4x canvas puts positions at 4x the 1024 px range. If it is ever wanted: start with the four `post_input` families, behind a switch that is off.
- Other upscaling routes looked at and not pursued: Ultimate SD Upscale (tile by tile, low denoise only), ControlNet Tile, reference-latent tile upscalers, SeedVR2, SUPIR, NVIDIA PiD (in core ComfyUI), DyPE. Core ComfyUI has no per-step tiled sampler (a request was closed as not planned).

**Known limits (also in docs/tiled-upscale.md).** ControlNet for transformer models is dropped while tiling (their residuals are token sequences; to do it right the control would have to be recomputed per tile, which needs the control object: it isn't passed to `apply_model`). Reference latents go whole to every tile. ComfyUI's memory estimate is for the whole latent. Region Genie's regions: see steps 1 and 2.

- Edit Mode: before the first run all configured edit LoRAs are added; Flux.1 dev vs Kontext can't be told apart; Krea 2 editing needs a third-party edit pack.
- Grow/shrink and flips change layer data; grow/shrink turns painted layers into pixels (a shape with nothing painted on it stays a shape).
